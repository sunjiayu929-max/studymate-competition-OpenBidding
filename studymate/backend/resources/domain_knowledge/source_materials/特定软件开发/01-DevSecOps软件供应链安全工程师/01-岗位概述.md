# 软件供应链安全工程师（DevSecOps）- 01 岗位概述

**岗位中文名：**软件供应链安全工程师（DevSecOps）。  
**岗位英文名：**DevSecOps Engineer / Software Supply Chain Security Engineer。  
**岗位定义：**该岗位将安全活动纳入软件开发生命周期，并以可验证的安全实践、制品和记录支撑交付。 [S1]

**岗位边界：**岗位工作不仅是上线前漏洞扫描，还包括需求阶段的安全要求、构建过程的依赖/来源证据、发布门禁和漏洞响应闭环。 [S1][S2]

**招聘样本使用方法：**本库优先使用能直达的国内单条职位详情页描述岗位需求；NIST、CISA、SLSA 与 GitHub 项目仅用于验证安全技术事实。职位中的薪资、年限和企业内部工具不泛化为行业统一标准。[J1][J2][S1][S2][S3]

## 典型业务场景

企业在 CI/CD 中对源代码、第三方依赖、容器镜像和基础设施即代码执行检查，并对通过检查的制品保留可验证来源。 [S1][S3]

SBOM 用于记录软件组件和依赖关系，从而支持组件漏洞影响分析和供应链透明度。 [S2]

## 与赛题的知识库切片对应

“威胁建模、SBOM、来源证明、安全门禁、漏洞响应”可分别作为领域专家 Agent 的可检索证据、实操指南主题和分阶测试题主题。 [S1][S2][S3]

## 岗位边界、输入与输出

该岗位把安全控制嵌入需求、编码、构建、发布和运维，而不是在上线前一次性做扫描；NIST SSDF 将准备组织、保护软件、产生安全软件和响应漏洞列为实践组。[S1]  
输入包括代码仓库、依赖锁文件、构建脚本、制品仓库、威胁模型、漏洞策略和发布审批；输出包括扫描报告、SBOM、签名与验证证明、例外清单、修复工单和复盘记录。[S1][S2][S3]  
供应链安全工程师与渗透测试、SRE 的边界是：渗透测试发现运行时攻击面，SRE 保证可用性，本岗位保证源代码到制品的完整性、可追溯性和安全门禁。[S1][S5]

## 典型场景

依赖升级前进行已知漏洞和许可证影响分析；CI 中执行 SAST、秘密扫描、依赖扫描和 IaC 检查；构建后生成 SPDX/CycloneDX SBOM；发布前验证签名和 provenance；发生供应商漏洞时按 SBOM 反查受影响服务。[S2][S3][S4]

## 能力分层（项目训练建议）

初级能解释 CVE、SBOM、最小权限并修复流水线告警；中级能设计分支保护、OIDC、签名和例外审批；高级能建立组织级 SSDF/SAMM 度量、威胁情报和跨团队响应机制。[S1][S5][S7]

## 国内真实招聘 JD 观察

拜耳在智联招聘公开的 DevSecOps Engineer 职位要求在 AWS、Azure、GCP 上建设可扩展、可靠、安全的基础设施，并使用 Terraform、CloudFormation、Ansible、Chef、Kubernetes 和 Docker 进行基础设施配置与编排。[J1]

该职位还要求建设 CI/CD、自动化测试、监控/日志/告警，集成安全扫描与漏洞评估到开发者工具和 CI/CD 流水线，并负责云网络中的 VPC 和安全组等配置；这与软件供应链安全工程师的工程职责直接相关。[J1]

## 真实 GitHub 工具补充

Trivy 是 Aqua Security 维护的开源安全扫描器，可作为漏洞、错误配置、秘密和 SBOM 等检查的工具参考；Syft 是 Anchore 维护的开源 SBOM 生成工具，可用于理解制品依赖清单生成流程。具体是否采用仍取决于组织的语言、制品和合规要求。[G4][G5]
