# 软件供应链安全工程师（DevSecOps）- 05 行业案例与官方技术文档

**实操案例：RAG 服务的供应链门禁。**可将“提交代码 - 依赖分析 - SBOM - 构建 - 签名 - 部署前验证 - 漏洞修复证据”设计为训练任务；该流程由 SSDF、SBOM、SLSA 和 Cosign 的公开能力组合而成，不宣称为某企业真实生产配置。 [S1][S2][S3][G1]

**训练任务 1：**给定一份依赖清单，要求学习者说明 SBOM 应保留的组件和版本信息，并给出漏洞影响分析的证据。 [S2][S4]

**训练任务 2：**给定一份 CI 配置，要求学习者定位过宽 Token 权限、未固定版本的第三方 Action 或明文密钥风险。 [S5]

**训练任务 3：**给定一个制品和 provenance，要求学习者说明部署策略应验证哪些证据、失败后如何形成例外和回滚记录。 [S1][S3]

**中文补充阅读：**CSDN 文章以中文介绍 DevSecOps 的安全左移和流程关系，可用于初学者术语预习；文章不是标准，具体控制仍以 NIST、OWASP 和 GitHub 官方资料为准。 [CSDN1]

## 训练案例与 Agent 闭环

**案例：依赖漏洞响应。**分析 Agent 读取 SBOM、CVE 严重度和运行暴露面；生成 Agent 生成升级 PR、测试计划和临时缓解；校验 Agent 检查 lockfile、许可证和回归结果；决策 Agent 根据风险策略批准、延期或回滚。[S1][S2][S6]  
**失败样本：**若只有漏洞标题、没有受影响版本或 SBOM 证据，系统必须标记“证据不足”，不能直接断言生产受影响。[S2]  
**资源映射：**讲义使用 SSDF/SAMM；实操使用 SBOM、Cosign 和 GitHub Actions；分阶题覆盖依赖升级、签名验证和组织治理。[S1][S3][S5]
