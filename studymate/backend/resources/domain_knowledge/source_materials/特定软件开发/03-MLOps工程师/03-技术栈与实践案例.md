# MLOps 工程师 - 03 技术栈与实践案例

**实验管理：**MLflow Tracking 记录运行、参数、指标和产物，可作为实验追踪能力的开源参考。 [G1]

**流水线：**Kubeflow Pipelines 提供机器学习工作流组件和管道的开源实现。 [G2]

**服务：**KServe 提供 Kubernetes 上模型推理服务能力的开源实现。 [G3]

**特征治理：**Feast 是开源 feature store，可参考其特征定义和线上/离线特征一致性治理。 [G4]

**监控：**Evidently 提供数据、模型和 LLM 评测/监控的开源工具。 [G5]

## 开源实战案例

**案例：MLflow + Kubeflow。**可将训练数据版本、实验运行、离线评估和注册审批组成可复现训练任务；该组合是基于两项目能力的培训设计，非二者共同发布的官方方案。 [G1][G2]

**案例：KServe 灰度服务。**可要求学习者为候选模型定义接口、部署资源、版本标识、观测指标和回滚条件。 [G3]

**案例：Feast + Evidently。**可要求学习者检查训练/服务特征一致性和数据漂移告警，并解释为何不能仅看服务是否存活。 [G4][G5]

## 技术栈分层与选型

**实验与注册：**MLflow Tracking 记录参数、指标、标签和制品；Registry 用于管理候选、生产和归档阶段。[S1][G1]  
**流水线：**Kubeflow Pipelines 以组件和 DAG 编排可重复步骤，适合 Kubernetes 环境；轻量项目可使用 GitHub Actions，但需补充制品和权限控制。[S2][S6]  
**服务：**KServe 提供 Kubernetes 推理资源、探针和流量管理；批处理场景可采用容器化定时任务。[S3]  
**特征：**Feast 管理特征定义、离线物化和在线读取，需明确 point-in-time join 防止未来信息泄漏。[G4][S5]  
**监控：**Evidently 可计算数据/预测漂移与质量报告；Prometheus、Grafana、OpenTelemetry 可补充系统指标，具体组合由平台约束决定。[G5][S4]

## 可复现案例卡

### 案例 1：MLflow 训练追踪与注册
输入：一个 sklearn 训练脚本、CSV 数据版本和 Git 提交号。[G1]  
步骤：启动 tracking server；在代码中记录参数、指标和模型；比较两次 run；将优胜模型登记为候选版本。[S1][G1]  
验收：页面能看到 run、代码版本、指标和模型文件；删除本地目录后仍可按记录复现。[S1]

### 案例 2：Kubeflow Pipeline 质量门禁
输入：预处理、训练、评估三个容器组件。[G2]  
步骤：编译 DAG；评估组件输出 JSON 指标；条件节点只允许达到基线的模型进入注册组件。[S2][G2]  
验收：任一组件失败可重试；门禁失败不会产生生产注册版本。[S2]

### 案例 3：KServe 灰度与回滚
输入：模型 URI、容器镜像、资源限制、旧/新版本。[G3]  
步骤：创建 InferenceService；配置 revision 和流量比例；发送固定回归集；发现错误率或业务指标恶化时切回旧 revision。[S3][G3]  
验收：请求日志可按版本区分，回滚后旧版本恢复服务且有事件记录。[S3]

### 案例 4：Feast 特征一致性检查
输入：离线特征表、在线存储和事件时间。[G4]  
步骤：定义 feature view；执行 point-in-time join；物化到在线存储；比较训练样本与在线读取值。[S5][G4]  
验收：不存在未来数据泄漏，线上请求能在 SLA 内取得同名特征。[S5]

### 案例 5：Evidently 漂移报告
输入：参考窗口、当前窗口、预测和标签（若已到达）。[G5]  
步骤：计算输入/预测分布差异；按用户群体切片；设置告警并关联再训练工单。[S4][G5]  
验收：报告保留窗口、样本量、指标和阈值；告警不会仅因样本不足而误触发。[S4]
