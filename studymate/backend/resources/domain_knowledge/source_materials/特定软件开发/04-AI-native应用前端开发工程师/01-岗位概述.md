# AI-native 应用前端开发工程师 - 01 岗位概述

**岗位中文名：**AI-native 应用前端开发工程师。  
**岗位英文名：**AI-native Frontend Application Engineer。  
**岗位定义：**该岗位负责把模型流式输出、工具调用、知识引用、Agent 状态和用户反馈转化为可操作、可解释的 Web 界面。 [S1][S2]

**岗位边界：**AI 前端不只是调用模型 API；还需建模生成中、取消、失败、重试、人工确认、引用和会话持久化等 UI 状态。 [S1][S3]

**招聘样本使用方法：**本库优先采用国内可直达的单条职位详情页描述 AI 前端与常规前端的真实招聘画像；W3C、MDN、SDK 文档和 GitHub 项目只用于验证协议、组件和工程实现。任何单条 JD 的薪资、年限和企业内部框架均不泛化为行业统一标准。[J1][J2][J3][S1][S2][S3][S6]

## 典型业务场景

流式对话工作台需要处理增量内容、停止生成和错误状态；Vercel AI SDK 的示例可作为 UI 实现参考。 [S1][G1]

多 Agent 可视化可使用节点图和状态机展示诊断、检索、生成、审核等阶段，但具体交互应由真实事件协议驱动。 [G2][G3]

RAG 前端需要展示文档上传/解析状态、检索来源、权限错误和无证据回答提示。 [S4][S5]

浏览器端本地推理是可选进阶方向，WebLLM 提供 WebGPU 推理的开源实现，但须评估设备兼容性、模型大小和内存。 [G4]

## 赛题知识库切片

“流式状态、引用展示、Agent 可视化、无障碍、安全渲染、断线恢复、端侧推理”可用作领域专家 Agent 的检索证据、实操指南和分阶测试题主题。 [S1][S6][S7]

## 岗位边界、输入与输出

岗位输入包括交互原型、模型事件协议、工具/Agent schema、RAG 引用格式、浏览器兼容矩阵与性能预算；输出包括可复用 AI 组件、流式 Hook、状态图、错误降级策略、测试和监控配置。[S1][S2][S3]  
前端应避免在浏览器暴露服务端密钥，也不能把不可信模型输出作为可执行 HTML 直接渲染；OWASP 将提示注入和不安全输出处理列为 LLM 应用风险。[S5]

## 能力分层（项目训练建议）

初级实现 React/TypeScript 页面与 SSE 增量渲染；中级完成 Agent 状态机、RAG 引用和浏览器回归；高级负责端侧推理、性能治理、可访问性与跨团队 AI 前端规范。[S1][S3][S6][G3][G4]

## 国内真实招聘 JD 观察

四川智服人力资源有限公司在智联招聘公开的“AI 前端开发工程师”职位列出 Vue、React、Node.js、ECharts、AI 大模型和智能体等关键词，并说明岗位负责大模型对话平台、AI 智能助手、AI Agent、RAG 知识库和智能创作等 AI 产品的前端研发与迭代。[J1]

该职位可作为“AI-native 前端”在国内招聘市场中的一条真实需求样例：前端工程师需要同时处理对话交互、Agent/RAG 产品界面和常规 Web 工程能力；具体框架、年限和薪资仅以该详情页为准，不能泛化为行业标准。[J1]
