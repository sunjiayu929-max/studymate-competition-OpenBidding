# AI-native 应用前端开发工程师 - 03 技术栈与实践案例

**前端基础：**JavaScript、TypeScript、浏览器网络/事件、响应式布局和无障碍语义是 AI 前端的基础；模型流式 UI 建立在这些 Web 能力之上。 [S1][S2]

**AI UI 与状态：**Vercel AI SDK 可作为流式 AI UI 参考，React 可作为状态驱动 UI 参考，XState 可作为复杂状态机参考。 [G1][G2][G3]

**编排可视化：**React Flow 是可用于拖拽节点、连线和自定义节点的开源图编辑库。 [G4]

**端侧推理：**WebLLM、Transformers.js 和 ONNX Runtime 均为浏览器端模型/推理能力提供开源实现；采用前须做设备实测。 [G5][G6][G7]

**质量工具：**Storybook 可用于组件文档与交互测试，Playwright 可用于浏览器 E2E 测试，Sentry JavaScript 可用于错误观测。 [G8][G9][G10]

## 开源实战案例

**案例 1：Vercel AI SDK 示例。**仓库示例目录包含多框架 AI 应用范例，可用于学习聊天、流式输出和工具交互；引用时应指向具体目录或提交。 [G1]

**案例 2：FastGPT。**FastGPT 是 Apache-2.0 许可的开源 AI 应用平台，可作为知识库与工作流产品形态的研究案例。 [G11]

**案例 3：WebLLM。**WebLLM 可作为浏览器离线推理、模型加载和 WebGPU 资源提示的技术案例。 [G5]

**案例 4：React Flow + XState。**将 React Flow 的节点图与 XState 状态图结合，可以设计 Agent 节点、运行状态和重试入口；该组合是工程建议，不宣称为官方联合案例。 [G3][G4]

## 分层技术栈与复现步骤

基础层采用 HTML/CSS、JavaScript、TypeScript、React；React 文档用于组件/状态设计，WCAG 2.2 用于键盘、焦点和动态反馈验收。[S1][S2]  
通信层使用 SSE/Fetch Streams、Vercel AI SDK 或模型厂商流式协议，必须处理 chunk 边界、取消、重连和错误。[G1]  
端侧层可选 WebLLM、Transformers.js 与 ONNX Runtime Web，选型前应测设备、模型体积、内存和隐私要求。[G5][G6][G7]

**复现 1：流式聊天。**从 Vercel AI SDK 的官方示例启动项目，观察增量消息、停止生成和异常 UI；扩展会话持久化后，验收刷新页面不重复 token。[G1]  
**复现 2：Agent 画布。**以 XState 定义分析/生成/校验节点事件，用 React Flow 展示节点与连线；验收是失败可重试、状态可追溯且不能因可视化直接执行未授权工具。[G3][G4]  
**复现 3：离线推理。**在支持 WebGPU 的设备加载 WebLLM 公共模型，使用 Worker 显示加载进度；验收是显存不足时降级、缓存模型后可离线使用。[G5]  
**复现 4：质量回归。**以 Playwright 覆盖中断、断网、恶意 Markdown 与键盘路径，再用 Sentry 记录脱敏异常；验收是失败会话可定位且不上传密钥/PROMPT 原文。[G9][G10]
