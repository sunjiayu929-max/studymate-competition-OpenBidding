# 前线部署工程师（FDE）｜行业案例与官方技术文档

## 一、已核验的公开来源

**Palantir AI FDE。**Palantir Foundry 提供 AI FDE 的官方文档入口，可作为研究 FDE 与企业 AI 平台协同、数据和工作流落地的官方技术资料。[S1]

**Accenture/Microsoft FDE 实践。**Accenture 2026 年新闻稿宣布面向企业 AI 规模化的 Microsoft FDE 实践；该来源可用于说明 FDE 已被咨询与企业技术服务组织作为 AI 落地模式讨论，但不能据此推断任一客户的具体项目效果。[S2]

**FDEOps。**该 MIT 开源项目给出以项目 fieldbook 记录客户事实、承诺、交付阶段和交接的工具化实践，可用于设计可审计的 FDE 交付记录。[G1]

**美团 CatPaw FDE。**智联招聘公开职位详情将 FDE 的工作拆成场景诊断与 Agent 定制开发、评测体系建设、从 POC 到生产的上线运营与持续调优，以及沉淀通用能力四部分；这是本库采用的国内真实招聘案例。[J1]

**Awesome-FDE-Roadmap。**该 MIT 开源路线图整理数据工程、云架构、咨询能力、企业 RAG、LLM 评测与交付模板等主题，适合作为学习路径与实操任务索引，而不是企业招聘标准。[G2]

**前线部署工程实践指南。**该 GitHub 指南以中文整理 FDE 从现场问题发现到生产交付的实践主题，并收录 Palantir、OpenAI、Accenture 等公开链接，适合中文学习者追溯并继续查证。[G3]

## 二、训练案例（明确标注为训练模拟，不伪称企业真实案例）

### 案例：制造现场巡检记录协同

输入：巡检员手工记录、班组长复核规则、已有业务系统和受限网络环境。训练者先产出用户/流程/数据/约束/验收证据表，再确定一条产线的最小试点，不直接承诺全厂上线。[G2][G3]

过程：分析角色核对资料授权和流程痛点；方案角色输出集成、权限、部署和回滚计划；校验角色核对数据、接口、用户任务和异常路径；决策角色基于证据选择扩大、返工或暂停。[G1][G3]

输出：试点范围、依赖清单、配置/联调记录、用户任务验收、遗留项、下一轮产品化建议。无法获得数据授权或验收证据时，应输出“暂不具备上线条件”。[G1][G2]

## 三、三类学习资源

**定制讲义：**FDE 的角色边界、客户现场发现、工程交付和产品反馈。[S1][G2][G3]  
**实操指南：**fieldbook 记录、试点计划、接口联调、验收和交接检查表。[G1][G3]  
**分阶测试题：**基础层识别流程和约束；实践层设计最小试点与异常处理；综合层平衡客户价值、风险、采用与可复制性。[G1][G2]
**指标训练题：**给定上线数据，判断采纳率、任务成功率、人工干预率与边缘案例分别指向何种改进动作。[J1]

## 国内招聘案例补充

美团 CatPaw FDE 是本岗位的核心国内招聘案例：页面把工作拆为客户场景诊断与 Agent 定制开发、评测体系建设、从 POC 到生产的上线运营和持续调优、以及共性能力沉淀。[J1]

J2-J7 是 AI 应用和智能体研发的国内招聘案例。它们可以用于比较 FDE 与应用研发、智能体开发、算法研发的协作关系；不得把这些相邻职位的标题、年限或企业内部流程当作 FDE 的普遍事实。[J2][J3][J4][J5][J6][J7]
