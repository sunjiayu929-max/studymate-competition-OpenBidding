# 前线部署工程师（FDE）｜岗位概述

**岗位中文名：**前线部署工程师。  
**岗位英文名：**Forward Deployed Engineer，FDE。  
**岗位定位：**FDE 是把产品、数据与 AI 能力带入客户真实业务流程的交付型工程角色。美团 CatPaw FDE 的公开职位把该工作描述为现场诊断、Agent 定制开发、评测、上线运营和通用能力沉淀；下文的技术资料用于补足其中的工程方法，而不是替代国内职位事实。[J1][S1][S2]

## 一、岗位边界

FDE 不等同于签约前主要证明可行性的售前，也不等同于只按需求实现功能的驻场开发。FDE 社区路线图把它描述为软件工程、AI/数据架构与咨询协作的复合角色；其关注点是总部产品与客户现场约束之间的落差。[G10]

FDE 既需要进入客户现场理解业务语言、约束和责任边界，也需要完成数据接入、接口联调、环境配置、权限确认、故障排查和验收证据留存；因此它是业务交付与软件工程之间的复合岗位。[G10][G11]

## 二、典型业务场景

1. **业务流程数字化：**把巡检、审批、排班、质量记录等人工流程转为可追踪的数据与任务流，并用真实使用者的完成情况作为验证证据。[G10][G11]  
2. **系统集成：**在客户已有系统、数据库、身份权限和网络约束下完成接口与数据联调；FDEOps 将一次交付过程抽象为 land、discover、plan、build、ship、close，并强调维护可核对的项目记录。[G11]  
3. **最小可行交付：**优先选择一条高价值、可测量的流程，以较小范围证明价值，再根据反馈扩大部署范围。[G10][G12]  
4. **上线与采用：**部署完成后观察真实用户是否能按流程使用，收集异常、培训缺口和配置问题，持续调整方案。[S1][G12]  
5. **产品反馈：**区分客户特有例外和可复用模式，把可复用的配置、需求和故障模式反馈给产品团队。[G1][G11]

## 三、岗位输入与输出

**输入：**客户业务目标、当前流程、数据/系统清单、可用权限、现场约束、相关责任人、验收口径和风险要求。[G10][G11]  
**输出：**价值假设、范围与依赖清单、集成方案、联调记录、部署检查表、验收证据、风险/遗留项、培训材料和产品反馈。[G11][G12]

## 四、国内真实招聘 JD 观察

美团在智联招聘公开的“CatPaw FDE 工程师（Forward Deployed Engineer）”岗位要求工程师深入客户现场诊断工作流，把业务痛点转为可量化、可验证的 Agent 问题，并基于 Skills、Subagent、Managed Agents 等能力完成定制化方案。[J1]

该 JD 将 FDE 交付具体化为：为能力建立评测集和打分标准，搭建离线评测与线上效果监控；从 POC 到生产跟踪采纳率、任务成功率和人工干预率；处理边缘案例、完成客户培训，并把共性需求回流产品路线图。[J1]

该 JD 同时列出 Java/Spring Boot、Go、Python 或 React/TypeScript 之一的工程基础，以及微服务、API、分布式系统、稳定性、性能、可观测性、Prompt、Function Calling、RAG 和 Agent 编排等能力。该要求仅代表该公开职位，不应被表述为所有 FDE 的统一门槛。[J1]

## 五、能力分层（项目训练建议，不是企业统一职级）

**基础：**能完成场景访谈、需求记录、简单 SQL/Python 数据核对和接口调试，并能将问题按数据、接口、环境或业务规则分类。[G10][G11]  
**进阶：**能将需求写成可验证价值假设，安排依赖与责任人，完成小范围部署、异常处理和验收复盘。[G11][G12]  
**综合：**能同时管理客户预期、技术风险、采用节奏和产品反馈，推动可复用交付模式而非重复的客户定制。[S1][S2][G10]

## 六、知识库使用范围

本岗位库用于检索场景调研、集成部署、验收、续约和产品反馈等问题。回答应说明所依据的章节和链接；当客户数据、授权或验收条件缺失时，应明确说明“无法据此确认”，不能用经验臆测替代证据。[G10][G11][G12]
