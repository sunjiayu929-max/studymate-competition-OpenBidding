# 前线部署工程师（FDE）｜核心职责与工作流程

## 一、核心职责

**场景发现与价值假设。**FDE 在进入实施前先确认当前流程、痛点位置、可用数据、约束、责任人和衡量成功的证据；FDEOps 的交付记录方法将 discovery 与 plan 置于 build 之前，避免在客户语境不清时直接开始开发。[G10]

**利益相关者协作。**FDE 需要使业务使用者、技术对接人和决策者对范围、风险、依赖、验收口径和下一步责任人形成共同预期；FDEOps 将“客户承诺、已达成事项和交付证据”保存在按项目隔离的 fieldbook 中，以便复核与交接。[G10]

**系统与数据集成。**FDE 按清单核实数据来源、接口契约、身份权限、网络环境、配置和异常处理；新的 FDE 路线图把数据工程、云架构和企业 RAG 列为交付所需的技术能力域。[G11]

**部署激活与采用。**部署不是安装结束。Palantir 的 AI FDE 文档将 AI FDE 放入实际平台与组织工作流中；FDE 项目需要用首批用户、真实任务和反馈判断采用，而不是仅凭演示完成判定成功。[S1][G12]

**验收、续约与产品反馈。**验收应覆盖功能、数据/接口、关键用户任务、异常处理和事先约定的业务证据；Accenture 的 FDE 实践新闻稿将 FDE 与企业 AI 规模化落地相联系，因而交付复盘应识别可复制能力而不是只关闭单个工单。[S2][G12]

**评测与线上效果监控。**美团 CatPaw FDE JD 要求为交付能力建立评测集和打分标准，并通过离线评测、线上效果监控、采纳率、任务成功率和人工干预率持续调优；这是国内公开 JD 中可用于训练的 FDE 指标样例。[J1]

## 二、标准 SOP

1. **需求访谈：**记录用户角色、当前流程、问题频率、约束和可验证结果，形成问题清单。[G10]  
2. **价值与范围确认：**写出最小目标、非目标、成功证据、风险、数据/系统依赖和责任人。[G10][G11]  
3. **方案拆解：**将数据接入、接口、权限、部署、培训和验收拆为可追踪任务，并标出前置条件。[G10][G11]  
4. **联调与原型验证：**先在受控环境验证数据、接口和关键路径；失败时记录输入、预期、实际结果和归属。[G10]  
5. **小范围部署：**选择一条流程和首批用户上线，观察完成率、异常和采用阻力，不直接扩大到全量用户。[G12]  
6. **验收与交接：**根据约定证据核验功能、数据、用户任务和异常路径，交接文档、权限和遗留问题。[G10][G12]  
7. **复盘与规模化：**区分可产品化模式与客户特例，形成可复用模板、风险库和下一轮改进项。[S2][G11]

## 三、AI FDE 补充 SOP

1. 将客户流程拆为“可由 Agent 处理、必须人工确认、暂不具备条件”的环节，并记录依据。[J1]  
2. 为候选能力建立输入样本、期望输出、评分规则和失败样本，先完成离线评测。[J1]  
3. 在小范围生产流量中观察采纳率、任务成功率、人工介入和边缘案例，再决定是否推广。[J1]  
4. 将稳定的 Skills、流程模板、评测集和失效模式回流产品，而不是只为一个客户维护孤立分支。[J1]

## 四、国内招聘证据对应

美团的 FDE 职位直接覆盖“现场诊断-定制开发-评测-生产运营-能力回流”的闭环，因此本文件的 AI FDE SOP 以 J1 为岗位事实依据。[J1]

智能体应用开发、AI 智能体开发和 Agent 算法工程师职位（J2-J7）不是 FDE 同义词，但它们是 FDE 在客户项目中常需要协同的应用研发角色；训练中应要求学习者能读懂这些职位的标题、边界和协作位置，而不是把它们当作 FDE 的替代名称。[J2][J3][J4][J5][J6][J7]

## 五、异常路径

数据缺失或口径不一致时，应停止依赖该数据的判断，标记缺口、确认数据责任人和补齐时间；不要用猜测值让验收“通过”。[G10]  
接口、网络或权限导致联调失败时，应保留请求/响应、配置版本、环境信息和复现步骤，按问题归属升级处理。[G10][G11]  
业务方临时扩大范围时，应重新确认价值、依赖、风险和验收口径；不能把未确认的新需求混入原交付承诺。[G10][G12]

## 六、交付物与验收证据

最低交付物包括业务问题与价值假设、范围/依赖清单、方案与配置记录、联调记录、部署检查表、用户任务验收结果、风险/遗留项和复盘反馈。[G10][G11][G12]  
建议将“关键用户能独立完成任务、数据和接口结果可复核、异常路径已演练、遗留项有责任人和日期”作为项目验收证据；具体数值阈值必须按客户合同和风险等级确认。[G10][G12]
