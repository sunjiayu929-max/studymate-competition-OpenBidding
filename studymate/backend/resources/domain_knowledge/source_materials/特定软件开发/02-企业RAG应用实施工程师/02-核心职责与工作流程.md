# 企业 RAG 应用实施工程师 - 02 核心职责与工作流程

**职责 1：需求和验收设计。**明确用户任务、知识边界、权限、更新频率、响应格式、延迟和拒答条件，并以评测集而非主观印象验收系统。 [S1]

**职责 2：知识接入。**将文档转换为可索引单元，并保留标题、来源、版本、页面、时间和权限等元数据。 [S2]

**职责 3：检索与生成。**选择关键词、向量、过滤和重排策略，并让答案关联检索证据。 [S3][S4]

**职责 4：安全和权限。**在将内容交给模型前实施访问控制、审计和敏感数据治理，不能仅依赖模型“不要泄露”的提示。 [S5]

## 标准工作流程

**步骤 1：**盘点知识源、数据所有者、授权范围和更新责任人。 [S1][S5]

**步骤 2：**解析、清洗、切分和标注文档，建立可重复的索引构建流程。 [S2]

**步骤 3：**对查询执行检索、过滤、重排和上下文组装，并记录命中文档。 [S3][S4]

**步骤 4：**生成带引用的答案，对无证据、冲突证据或越权请求执行拒答/澄清策略。 [S1][S5]

**步骤 5：**使用离线评测、用户反馈和版本化测试集持续检查检索与回答质量。 [S1][S6]

## 交付物与建议考核

交付物包括数据字典、授权清单、解析/切分规则、索引脚本、提示模板、评测集、引用样例、监控与回滚说明。 [S1][S2][S6]

建议记录 Recall@k、引用正确性、无依据回答率、拒答正确性、越权拦截、延迟和成本；阈值需由数据风险和业务验收样本确定。 [S1][S6]

## 国内招聘证据对应

广东金汇流信息技术有限公司珠海分公司的“AI 应用开发工程师/RAG 架构师”是本岗位的同名招聘样本，其职位页面是本文关于 RAG 实施岗位画像的国内事实来源。[J1]

大模型应用、AI 应用和智能体工程职位（J2-J7）是 RAG 项目常见的相邻研发角色。它们适合用于训练需求澄清、知识接入、检索、生成和交付协作的岗位语境，但不能被表述为“所有 RAG 架构师均必须满足”的统一要求。[J2][J3][J4][J5][J6][J7]

## 职责卡

|职责|输入与动作|输出/验收|
|---|---|---|
|需求与权限分析|访谈问题、角色、数据分级|范围说明、ACL 矩阵和不可回答边界。[S2][S6]|
|文档处理|PDF/Word/HTML、版本和页码|可追溯 Document/Node，保留标题、页码、更新时间。[S3]|
|切分与索引|分段规则、embedding、关键词字段|可重建索引脚本和统计；抽样能定位原文。[S3][S4]|

## 标准 SOP

1. 需求澄清：定义用户、问题类型、数据边界、SLA 和成功指标。[S2]  
2. 数据盘点：确认来源、授权、版本、敏感字段和更新频率；拒绝无授权数据。[S6]  
3. 解析切分：保留结构、表格、页码和元数据，比较固定长度、语义和层级切分。[S3]  
4. 索引构建：建立关键词、向量或混合索引，记录 embedding 模型和版本。[S4]  
5. 检索编排：先做权限过滤，再召回、重排和上下文压缩；记录每个 chunk 的分数。[S2][S4]  
6. 生成与引用：要求模型只依据证据回答，引用文档名/页码/段落；证据不足时解释缺口。[S2][S5]  
7. 评测上线：用黄金集和对抗集评估召回、忠实度、引用、拒答、延迟和成本。[S5][S6]  
8. 反馈迭代：分析失败属于解析、召回、提示、权限还是模型原因，版本化修改并回归。[S2][S5]

## 异常、回滚与交付物

解析失败保留原文件并进入人工队列；索引版本不一致时切换上一索引；检索无证据时拒答；越权命中时在生成前拦截并记录审计；模型输出与证据冲突时降低置信度并要求人工复核。[S2][S6]  
交付物包括数据字典、授权矩阵、解析/切分配置、索引脚本、提示模板、评测集、引用样例、监控面板、版本清单和回滚手册。[S2][S3][S5]
