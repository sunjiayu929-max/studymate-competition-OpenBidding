# 企业 RAG 应用实施工程师 - 01 岗位概述

**岗位中文名：**企业 RAG 应用实施工程师。  
**岗位英文名：**Enterprise RAG Application Implementation Engineer。  
**岗位定义：**RAG 将检索到的外部知识与生成模型结合，以处理知识密集型任务；实施岗位的核心是把这一方法落实为授权数据、检索、生成、评测和运营链路。 [S1][S2]

**招聘样本使用方法：**本库以国内可直达的单条职位详情页观察 RAG、AI 应用与 Agent 研发中的岗位需求；论文、官方文档和开源仓库只用于补足技术原理。具体企业的薪资、年限和工具清单不泛化为行业统一标准。[J1][J2][J3][S1][S2][S3]

**岗位边界：**企业 RAG 实施不仅负责聊天界面或模型调用，还需要定义文档范围、权限、数据更新、引用、拒答与评测。 [S2][S3]

## 典型业务场景

企业制度、产品文档、工单和技术手册可经解析、切分、索引和检索后，为受权限控制的问答或辅助工作流提供上下文。 [S3][S4]

检索结果的来源和证据范围需要随答案呈现；无证据或越权时应拒答、澄清或转人工，而不是生成确定性结论。 [S5][S6]

## 赛题知识库切片

“需求澄清、文档解析、切分、混合检索、重排、引用、权限、评测、反馈更新”可作为专家 Agent 检索切片和分阶实操主题。 [S2][S3][S5]

## 岗位边界与业务场景

企业 RAG 实施工程师把业务资料转化为可检索知识，并将检索证据注入生成上下文；RAG 原始论文将流程描述为检索外部知识后增强生成，以提升知识密集任务的可验证性。[S1]  
岗位负责需求访谈、数据授权、解析切分、索引、召回/重排、提示模板、评测、上线和运营反馈；不应把未经授权的文档直接上传，也不应把语言流畅当作答案正确。[S2][S6]  
典型场景包括制度问答、售后知识助手、研发文档搜索、合同条款检索、客服坐席辅助和多部门权限隔离知识库。[S2][S6]

## 输入、输出和能力分层

输入是文档、元数据、权限规则、问题样本、延迟/成本目标；输出是解析与切分配置、向量/关键词索引、检索链路、引用答案、评测集、监控与回滚文档。[S2][S3][S5]  
初级完成单一数据源索引和引用展示；中级完成混合检索、重排、权限过滤和自动评测；高级处理多租户、增量更新、成本治理、越权和抗提示注入。[S2][S4][S6]

## 国内真实招聘 JD 观察

广东金汇流信息技术有限公司珠海分公司在智联招聘公开的“AI 应用开发工程师/RAG 架构师”职位要求参与 RAG 的数据处理、索引构建、召回排序和提示词工程，并处理 PDF、扫描件和复杂表格等非结构化资料。[J1]

该职位列出 Milvus/Qdrant 等向量数据库的检索性能优化、对接 OpenAI/智谱/通义千问/DeepSeek 等模型、Python 与 FastAPI/Flask API 开发、Vue/React 测试界面、API 成本与检索延迟优化；这些是企业 RAG 实施中可观察的真实岗位要求。[J1]
