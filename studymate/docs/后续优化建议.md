# StudyMate 后续优化建议

## 本轮已经完成的基础工作

- 将介绍页接入未登录根路径，保留已确认的真人学习主视觉、北京时区时间、产品实拍、真人助教片段、动态学习星系和明确登录入口。
- 已恢复 5 门预设课程，演示种子当前含 1709 条知识片段；初始化与增量导入不会覆盖现有用户、画像、会话和笔记。
- 课程选择页改用真实教材封面，保留课程名、简介、知识片段数和进入按钮，不显示“主要参考教材”等额外标记。
- 修复画像对话首屏高度：中间对话区和右侧画像区独立滚动，输入框在桌面首屏内稳定可见。
- 把概念讲解拆成上方“AI 视频讲解”和下方“交互画板”；视频区提供中央播放、暂停、重播、进度、音量和全屏入口。
- TTS 改为完整句队列：首句生成后即可开播，播放当前句时预取后两句，保持顺序并支持打断；普通朗读、实时语音和概念讲解共用这一策略。
- 加入统一真人数字人资产：全局右下角是可见的真人助教入口，按页面偶尔给出提示；实时语音页使用全身数字人，并表现聆听、思考、讲解和暂停状态。

## 上线前优先完成

### 1. 配置并压测语音服务

当前没有正式 TTS/ASR Key，因此本轮只能验证前端队列、取消、降级和状态机，不能验证真实首包延迟与音频质量。接入 Key 后建议记录：

- 首句 TTS 首包时间、P50/P95 生成耗时；
- 句间空白时长和连续播放失败率；
- 用户打断到停止播音的延迟；
- 不同音色的中文数字、英文缩写、公式和代码发音效果；
- 限流、余额不足、网络断开时的降级提示。

理想目标是首句在模型开始回答后约 1.5～2.5 秒内出声，后续句子基本无可感知空档。

实时语音还存在多轮会话故障：当前第一轮通常可以完成，但第二轮开始后回答会异常停止，界面提示“本次回答已停止，当前内容已保留”，同时可能出现“语音识别服务返回异常”，继续监听或重试也无法稳定恢复。修复时应重点排查每轮结束后的 ASR WebSocket/录音资源释放与重建、生成请求和 `AbortController` 是否被错误复用、TTS 队列是否真正排空、播放结束回调是否重复触发，以及“聆听/生成/播放/暂停”等状态是否发生竞态。验收标准至少覆盖连续 5 轮语音问答、播放中打断后继续提问、识别失败后重连，以及切换文字模式再返回语音模式。

### 2. 数字人升级为短循环视频素材

目前使用统一真人静态全身图、轻微呼吸/位移、状态气泡、讲话波形和非常轻的口型提示，已经能建立“真人助教在场”的感觉。若需要评委近距离观看时更可信，建议后续制作同一人物的 4 段短循环视频：

- 待机：自然呼吸和偶尔眨眼；
- 聆听：轻微点头；
- 思考：视线略微偏移后回正；
- 讲解：中性口型循环和小幅手势。

视频统一机位、服装、光线和背景，前端只按状态无缝切换。无需做复杂 3D，也不建议追求逐音素级口型。

右下角全局助教入口还需改为可拖动的“悬浮数字人”，而不是一个人物按钮：使用透明背景人物素材，移除当前包裹人物的白色卡片、边框、固定文字区和所有矩形底板，让人物轮廓直接融入网页；确保头部与全身完整露出、不被容器裁切。用户可以在页面内拖动人物并记住最近位置，拖动时不能误触打开；点击人物或头顶气泡才打开助教。悬停时只给予轻微呼吸、位移或柔和投影反馈，功能提示改成偶尔出现在人物头顶的悬浮气泡，平时不占固定空白。

实时语音页的数字人舞台也采用相同的透明悬浮方案：当前人物偏小，素材自带的米白色矩形底板与页面白色/暖白色背景明显分层，内层边框和留白进一步强化了“贴照片”的感觉。后续应将人物明显放大，彻底去除素材底板和多余边框，让透明人物直接融入整块语音舞台；人物可在舞台安全范围内拖动调整位置，并避免拖动与点击、暂停等操作冲突。同时保证头部、脚部和全身轮廓完整，状态气泡不能遮挡面部，聆听、思考、讲话、暂停和轻量口型等状态反馈继续保留。

### 3. 数据初始化做成明确的运维流程

本轮新增的增量导入脚本适合恢复空课程目录，并且不会改用户数据。正式部署时建议：

- 在部署文档中明确“全新环境使用种子库、已有环境使用增量导入”；
- 给导入脚本加版本号和迁移记录表；
- 启动健康检查增加课程数、知识块数和向量数；
- 管理端增加只读的数据状态卡，避免再次出现页面空白但不知道原因。

### 3.1 AI 助教支持模型切换

在 AI 助教顶部增加紧凑的模型选择器，提供 Qwen、DeepSeek、MiMo 三项，并显示当前模型；默认模型仍由服务端配置决定。选择只影响助教本轮及后续回答所使用的生成模型，课程上下文、RAG 检索结果、附件解析和学习画像继续共用，避免切换模型后丢失对话语境。

后端应使用受控的 provider 白名单按请求路由，分别读取现有的 `QWEN_*`、`DEEPSEEK_*` 和 `MIMO_*` 服务端配置，绝不能把真实 Key 发送到浏览器。前端记住用户最近选择，可提供“推荐”标记和简短能力说明；当某个模型未配置、无权限或调用失败时应明确提示并允许切回其他模型，不能静默换模型。普通文字助教与实时语音助教应使用同一选择结果，TTS/ASR 引擎不随回答模型改变。

### 3.2 用户私有知识库

在现有课程 RAG 基础上增加用户私有知识库：用户可以创建、重命名和删除自己的知识库，上传 PDF、PPT/PPTX、Word、Markdown、TXT 等学习资料，查看解析与向量化进度，并选择某个知识库绑定当前课程或助教会话。系统需要明确区分系统课程库与用户私有库，检索结果标注来源文件和页码，删除资料时同步清理对应文本块与向量，且不同用户之间严格隔离。

比赛版本完成“创建知识库—上传资料—自动解析—助教引用回答”的完整演示闭环，不建设面向开发者的开放平台、API Token 管理或接口调试台。Qwen、DeepSeek、MiMo 三个回答模型共用同一套检索结果，切换模型不会重新建库。

### 3.3 登录后采用分组式左侧导航

随着知识库和模型切换加入，现有顶部一级菜单会过于拥挤。登录后的应用壳应统一改为可折叠左侧导航：一级菜单作为可展开/收起的分组，内部嵌套二级入口，当前分组和当前页面均有清晰但克制的高亮；左栏展开约 224px，折叠后保留约 72px 图标栏。侧栏品牌下方放一张紧凑的“当前课程”卡，可直接切换课程；顶部工具栏只保留当前页标题/路径、页面相关操作、通知和用户入口。回答模型仅在助教、资源工坊、PPT 生成等相关页面显示，朗读音色仅在支持语音的页面显示，避免无关页面出现无效控件。

根据当前实际路由与计划新增功能，建议结构：

- 学习中心：今日学习、课程空间、学习画像；
- 学习资源工坊：作为独立一级入口，直接进入多 Agent 学习资源生成主流程；
- AI 学习工具：AI 助教、实时语音、可视讲解、PPT 生成；
- 知识与笔记：知识库、智能笔记；
- 练习与成长：智能测验、学习报告。

“RAG 检索测试”放在知识库页面内部页签，不继续占用一级导航；“可视讲解库”放在可视讲解页面内部；新手指引、反馈中心和仅管理员可见的测试管理固定放在侧栏底部辅助区。资源详情、工作台成果详情、测验作答、RAG 原文等上下文页面不出现在菜单中，只通过上级页面进入并显示返回路径。

“学习资源工坊”是产品最高频、最具差异化的多 Agent 主流程，不归入“创作中心”等普通分组。侧栏中可将它放在学习中心之后，并通过专属图标、克制的金色状态点或“7 Agents”小标识强化识别，但不能做成破坏整体留白的大色块按钮。“创作中心”不再单独设置；PPT 生成归入“AI 学习工具”。

最终侧栏层级再做一次高频优化：品牌和当前课程卡下方，直接常驻“今日学习”和“学习资源工坊”两个最高频入口，不要求用户先展开分组；学习中心分组只保留课程空间与学习画像。其余一级分组采用手风琴展开，默认展开当前页面所属分组，并记住用户上次的展开与折叠状态。多 Agent 正在生成时，学习资源工坊旁显示低干扰运行点和进度数字；报告或反馈有新内容时显示小圆点，禁止堆叠彩色徽章。

侧栏底部固定新手指引、反馈中心、管理员测试管理和用户账号/退出，主导航区域独立滚动；折叠状态下通过图标、悬浮提示和清晰的活动指示线保持可识别。进入学习宇宙首屏时侧栏完全退场，进入暖白学习桌面后再出现；实时语音、测验作答和全屏讲解时自动折叠。导航必须支持键盘操作、触屏抽屉和减少动态模式，并确保可拖动数字人的活动边界不会覆盖侧栏。

只借鉴分组嵌套的信息架构，不照搬参考图的浅蓝后台风格。StudyMate 继续使用暖白底、低饱和蓝灰与少量金色点缀，保持大面积内容留白。所有登录后页面应由路由级统一应用壳提供侧栏，避免每个页面自行渲染导航导致混用或漂移；实时语音、测验作答和全屏讲解等沉浸页面可自动折叠侧栏。窄屏下变为抽屉或精简底部导航，可拖动数字人的活动边界也要避开展开后的侧栏。

### 3.4 PPT 生成

在“AI 学习工具”分组增加功能入口“PPT 生成”。用户可以输入主题，也可以选择当前课程、私有知识库或上传的 PDF/PPT/Word 作为资料来源；设置受众、用途、页数和视觉风格后，系统先生成可编辑大纲，用户确认后再生成完整演示文稿。

比赛版需要形成真实可用闭环，而不是只展示 PPT 图片：页面提供缩略图预览、拖动排序、单页重写、标题与正文编辑、引用来源查看，并导出真正可编辑的 `.pptx`。生成结果至少包含封面、目录、章节内容、案例/图表页、总结和问答页；优先使用受控的项目模板与版式系统，限制每页文字量，避免出现明显的 AI 堆字。后端生成时复用用户选择的 Qwen、DeepSeek 或 MiMo，并让课程 RAG/私有知识库为内容提供依据。

### 3.5 首页学习宇宙与实时学习报告

登录后的“今日学习”首页首屏改为学习宇宙主舞台，而不是把大屏藏在学习报告中。它面向日常使用和评委第一眼展示，实时汇总当前课程、累计学习时长、已学习知识点、生成资源、笔记、测验与画像变化；原有今日路线、待办、最近记录和画像速记继续保留在主舞台下方，不能为了视觉效果丢失首页的可执行性。

主舞台延续介绍页的星球语言：把学习者放在中央核心，知识、测验、笔记、资源和 Agent 成果以轨道、节点和成长连线围绕展开；各节点本身就是清晰的功能入口，点击后进入对应页面。实时学习事件到达时对应节点点亮、数字平滑滚动并产生轻微脉冲，薄弱点改善时路径颜色自然过渡。进入首页只播放一次短促的镜头推进和轨道展开，随后保持低干扰动态；使用暖白、蓝灰、炭黑和低饱和金色，避免满屏粒子、霓虹描边和无意义循环。新用户没有数据时展示可操作的引导星图，演示账号则使用真实已有历史。

首页宇宙主舞台采用一套独立于应用正文的沉浸式色彩，不强行沿用暖白界面：以近黑宇宙底、石墨蓝、烟紫、冷灰青和低饱和铜金为主，局部高光可以更鲜明，但避免高饱和亮蓝和廉价霓虹。用户刚进入首页时，首屏是接近全屏的宇宙场景，常规左侧导航与暖白内容暂时隐藏或降到最低存在感；向下滚动或点击“进入今日学习”后，通过星空变淡、背景亮度上升和内容层推进，自然切换回项目现有的暖白色应用壳、左侧菜单和今日学习内容。保留“返回学习宇宙”入口，并支持减少动态效果。

宇宙首屏必须提供一眼可见的主入口，按钮文案使用“进入今日学习”或“进入学习桌面”，不要写“进入首页”，因为用户已经处于首页路由。入口放在视觉中心下方或中央学习者核心附近，采用高对比但克制的实体按钮并配清晰箭头；点击后播放短暂退场过渡，随后定位到正常学习桌面的顶部。中央学习者星球也可以触发同一动作，但按钮必须独立存在，不能只依赖用户猜测星球可点击；键盘、触屏和减少动态模式下同样可正常进入。

动态层次可以包含：多层星空视差、缓慢轨道运行、星球自转与光照变化、学习事件沿轨道形成的能量路径、偶尔从远景掠过的小型飞船、低频流星或遥远彗尾、鼠标移动产生的轻微镜头偏移，以及 Agent 工作时出现的短暂信号脉冲。飞船和流星必须低频、轨迹避开文字与可点击节点，不能反复抢夺注意力；所有动态在用户滚动离开宇宙首屏后停止或显著降频，避免继续消耗性能。

现有“学习报告”取消“必须点击后才生成数据”的门槛，改为进入页面即可看到实时更新的数据与图表：知识掌握/能力雷达、正确率与学习节奏趋势、薄弱点变化、学习路径时间线、最近事件和下一步建议持续同步。报告中的数值、图表和事件流通过聚合接口加短轮询或服务端事件流增量刷新；AI 长文本阶段总结不随每个小事件反复生成，而是在完成测验、完成一轮资源学习或画像发生实质变化后后台更新。仍可保留“重新生成阶段总结/导出报告”作为明确操作，但用户不需要先点击按钮才能看到报告主体。

## 演示效果可继续提升

### 4. 介绍页与应用内数字人统一人物

介绍页现有真人讲师视频与应用内新数字人不是同一人物。比赛版本可以接受，但最高完成度的方案是重新生成或拍摄同一人物素材，让介绍页、全局助教和语音页形成连续体验。

介绍页星系模块还需修复标题重叠：当前最上方轨道及运行星球会进入标题下方说明文字的行高范围。应为标题与说明区保留独立的纵向安全区，将星系舞台整体下移或压缩最高轨道半径，并限制所有星球动画的顶部边界；不同窗口高度和缩放比例下也不能侵入文字区域。

### 5. 为 AI 视频讲解增加真实时间轴

当前进度条主要表达播放状态。下一步可让每个讲解节拍提供预计时长，并根据实际音频 `duration` 累加为总时长，从而实现：

- 可拖动时间轴；
- 当前时间 / 总时长；
- 拖动后同步跳到相应动画节拍；
- 字幕逐句高亮；
- 0.75×、1×、1.25×、1.5× 播放速度。

同时修复播放器底部大面积深色空区：当前视频外层容器高度大于 Canvas、字幕和控制栏的实际内容高度。应让播放器随内容自适应收缩，为 Canvas 设置稳定的宽高比与最大高度，并让普通模式与全屏模式分别计算布局，避免控制栏下方继续保留空白“黑边”。

### 6. 课程封面版权与离线资源治理

真实书封能显著提升可信度，但公开商业发布前需要再次核对出版商的展示授权。可以在不改变界面的前提下：

- 保存资源来源、ISBN、抓取日期和授权状态；
- 统一压缩为 WebP/AVIF，并保留 JPEG 回退；
- 生成 1×/2× 响应式尺寸；
- 在封面加载失败时使用项目内置的课程图形回退。

### 7. 评委演示模式

建议增加一个不打扰正常用户的“评委演示”开关：

- 自动选中机器学习课程；
- 预置一条高质量 RAG 查询、一条可视讲解和一轮语音对话；
- 对尚未配置的外部服务显示“演示降级”而不是报错；
- 全流程控制在 3～5 分钟，支持一键复位。

## 工程质量建议

### 8. 自动化端到端回归

建议覆盖最关键的评委路径：

1. 介绍页进入登录；
2. 登录后选择课程；
3. RAG 搜索返回来源；
4. 建立画像时输入框始终可见；
5. AI 视频讲解首句开播、暂停和打断；
6. 全局数字人打开助教抽屉；
7. 语音服务不可用时仍能完整阅读文字回答。

测试环境不要自动申请麦克风、摄像头或全屏权限，相关能力使用模拟接口验证状态机。

### 9. 性能预算

- 介绍页大图和视频使用首屏优先级、延迟加载与移动端低码率版本；
- 数字人图片输出 WebP，并控制在约 250 KB；
- 重型图表、编辑器和概念动画继续按路由拆包；
- 记录 LCP、INP 和长任务，目标是常用评委电脑上首屏 LCP 小于 2.5 秒。

### 10. 可观测性与隐私

- 记录模型、RAG、TTS、ASR 各阶段耗时，但不记录原始麦克风音频；
- 前端错误带页面、课程和请求 ID，避免采集完整对话正文；
- 画像页明确说明哪些信息会被提取、如何重置和删除；
- 外部教材、视频与搜索结果保留来源链接和抓取失败原因。
- 清理退出登录时的事件上报竞态：当前 `/api/auth/logout` 成功清除 Session 后，前端可能继续提交残留的 `/api/events/batch`，从而产生一次无害但醒目的 401。退出流程应先停止或清空行为事件队列；事件上报在明确退出态遇到 401 时静默丢弃，不触发重复登录提示，也不污染演示日志。

## 推荐执行顺序

1. 配置真实 TTS/ASR Key，验证流式句子队列和打断。
2. 做同一人物的 4 状态短视频，替换静态数字人状态动画。
3. 完成真实视频时间轴与倍速。
4. 增加数据健康卡和部署迁移记录。
5. 补齐评委主路径端到端测试和性能预算。
