# StudyMate 安全离线模式修复交接

日期：2026-07-29
范围：后端配置加载、外部 provider、私有知识任务、安全启动与自动回归

## 1. 根因

第四阶段第一次安全巡检曾用 PowerShell 把外部服务环境变量赋为空字符串。PowerShell 会把空字符串视为删除变量，后端的 Pydantic `BaseSettings(env_file=".env")` 随后从项目工作目录回读真实 `.env`。临时 TXT 一度显示向量检索就绪，因此不能排除发生过一次 Embedding 请求。

发现后当时已立即停机并改用不含 `.env` 的目录隔离，但“清空变量”和“换工作目录”都不是可长期复用的代码级边界。本次修复保留该历史事实，不把临时处置描述成最终方案。

## 2. 正式修复

安全离线模式统一使用进程环境开关 `STUDYMATE_SAFE_OFFLINE=1`，并形成两层保护：

1. 配置层在创建 `Settings` 前读取进程环境。开关开启时传入 `_env_file=None`，完全不读取项目 `.env`。
2. 运行层清空父进程中可能残留的外部服务配置，并安装出站网络保险丝，阻断外部 DNS、TCP 与 UDP。

受控能力包括：

- Qwen、DeepSeek、MiMo、星火及 Qwen-VL；
- Embedding；
- 讯飞 ASR/TTS、CosyVoice；
- 私库 OCR 插件和拍照识题 OCR；
- SMTP；
- Piston；
- B 站、人才呀、arXiv、Crossref、豆瓣图书、CSDN、掘金等公开站点解析。

这些入口会在创建网络 client/provider 前短路。人才呀返回内置兜底目录，阅读解析返回空，B 站返回安全离线态。Piston 能力接口标记 `available=false`，代码执行返回明确离线提示。

私有知识库任务当前使用 FastAPI 进程内 `BackgroundTasks`，没有外部队列实现。安全离线模式仍允许该本地任务运行，但 `has_embedding_key()` 永远为假，因此 TXT 只能完成为 `ready_keyword`，向量进度为 0，分片向量为空。扫描 PDF 的 OCR 仍为 `required_unconfigured`，不会伪装成功。

## 3. 使用命令

PowerShell、`cmd.exe` 和 bash 都直接调用同一个 Python 启动器：

```bash
cd backend
python scripts/run_safe_offline.py \
  --database-path /absolute/path/studymate-safe.db \
  --private-knowledge-dir /absolute/path/studymate-safe-private
```

Windows 下把两个路径替换为 Windows 绝对路径。启动器要求：

- 数据库和私库目录必须显式提供且为绝对路径；
- 只允许监听 `127.0.0.1` 或 `::1`；
- 不使用 reload/spawn；
- 不启动 Piston；
- 不读取或修改真实 `.env`。

不要把 `STUDYMATE_SAFE_OFFLINE` 写进 `backend/.env`。决定“是否读取 `.env`”的开关必须在读取文件之前由进程环境或正式启动器设置。

## 4. 自动验证

定向回归：

```bash
cd backend
python -m unittest tests.test_safe_offline_mode -v
```

完整后端验证：

```bash
python -m compileall -q app scripts
python -m unittest discover -s tests -v
```

`tests/test_safe_offline_mode.py` 覆盖：

- 临时 `.env` 含固定假 Key 时，安全模式完全跳过该文件；
- 父进程同时带固定假 Key 时，所有 provider 仍为未配置；
- 进程级 DNS/出站保护生效；
- LLM、Embedding、WebSocket、HTTP、SMTP 和 Piston mock 调用均为 0；
- B 站、人才呀、阅读解析走安全离线分支；
- 临时 TXT 最终为 `ready_keyword`，向量调用 0 次、向量字段为空。

本次实际结果：编译检查通过，完整后端 unittest 共 52 项全部通过。正式启动器使用全新临时
SQLite/私库目录启动成功；真实本地 HTTP 冒烟确认 LLM 配置数 0、ASR/TTS/OCR/Piston/
外部队列不可用、代码运行走离线 mock。冒烟进程已停止，临时目录已清理。由于使用空白隔离
SQLite，本次接口冒烟的课程数为 0，不复用或修改真实运行库。

接口冒烟至少确认：

- `GET /api/ping`：`safe_offline=true`、`llm_configured=false`；
- `GET /api/tutor/models`：Qwen、DeepSeek、MiMo 配置数为 0；
- `GET /api/voice/status`：ASR/TTS 均未配置；
- `GET /api/run/capabilities`：`available=false`、`mode=safe_offline`；
- 管理员数据健康：OCR 不可用、外部队列不可用且模式为 `in_process`。

## 5. 剩余边界

- 后端安全离线模式不拦截用户浏览器主动点击第三方链接；浏览器级全离线验收继续使用 E2E 路由 mock 或浏览器网络策略。
- 本模式不验证任何真实 LLM、Embedding、ASR、TTS、OCR、SMTP、Piston 或公开站点的连通性、费用、配额、性能和质量。
- 当前出站保险丝是进程级保护；若未来引入子进程、独立 worker 或外部队列，必须让每个进程在导入应用前继承安全开关，并补对应的 0 外联回归。
- 普通开发和生产启动行为不变，仍可按 `.env` 配置外部能力；安全模式不是生产部署 Profile。
