# StudyMate 密钥管理指南

> 最后核对：2026-07-17。本文只说明保存位置和操作流程，不记录任何真实凭据。

项目真实凭据只保存在 `backend/.env`，该文件权限应为 `600`，且不得进入 Git、镜像、
截图、聊天记录或交付文档。

本地开发和服务器生产环境必须分别维护 `.env`，不要让同一组高权限 Key 在所有机器之间长期复用。

## 安全离线巡检

不允许外联的测试不要通过清空环境变量模拟“未配置”。PowerShell 把空字符串赋值视为删除变量，普通后端启动仍可能从当前目录的 `.env` 回读真实凭据。

统一使用：

```bash
cd backend
python scripts/run_safe_offline.py \
  --database-path .runtime/studymate-safe.db \
  --private-knowledge-dir .runtime/studymate-safe-private
```

启动器在导入配置模块前通过进程环境设置 `STUDYMATE_SAFE_OFFLINE=1`，使后端完全跳过项目 `.env`，并把父进程中残留的模型、Embedding、语音、OCR、SMTP 和 Piston 配置覆盖为不可用；出站网络保险丝提供第二层保护。该开关不得写进 `backend/.env`，因为“是否读取 `.env`”必须在读取文件之前由进程环境决定。

安全离线模式只接受显式隔离的本地 SQLite 路径和私有资料目录。不要用真实运行库做巡检，也不要启动 Piston 或用真实服务做“连通性验证”。

## 什么是轮换

轮换不是重命名或移动密钥文件，而是：

1. 在服务商控制台创建一组新凭据。
2. 把新值更新到 `backend/.env`。
3. 重启后端并验证对应功能。
4. 在服务商控制台撤销旧凭据。
5. 删除保存旧值的临时文件和副本。

只有完成第 4 步，旧密钥才真正失效。

## 本项目的凭据类别

| 配置 | 用途 | 轮换影响 |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | 主流程 LLM | 重启后端后生效 |
| `SPARK_API_KEY` | 讯飞星火模型 | 重启后端后生效 |
| `MIMO_API_KEY` | 小米 MiMo 模型 | 重启后端后生效 |
| `QWEN_API_KEY` | Qwen、视觉、Embedding；CosyVoice 可回退使用 | 需要验证助教、图片、检索和语音 |
| `COSYVOICE_API_KEYS` | CosyVoice 独立 Key 池 | 逗号分隔，逐个替换并验证 |
| `XFYUN_APP_ID` / `XFYUN_API_KEY` / `XFYUN_API_SECRET` | 讯飞 ASR/TTS | 作为同一应用凭据组合一起更新 |
| `SMTP_PASSWORD` | 邮箱 SMTP 授权码 | 不是邮箱登录密码；更新后验证验证码邮件 |
| `AUTH_SECRET_KEY` | StudyMate 会话签名 | 更换后现有登录会话全部失效 |

`SESSION_COOKIE_SECURE`、`CORS_ORIGINS`、模型名称和服务地址不是秘密，但属于环境配置；生产值仍不应随意复制到不受控环境。

## 建议验证

更新凭据后不要输出具体值，只检查配置状态和功能：

```bash
chmod 600 backend/.env
curl http://localhost:8000/api/ping
```

随后分别验证工作台生成、助教、图片理解、语音和注册邮件。确认新凭据可用后再撤销旧凭据，
避免先撤销导致服务中断。

推荐顺序是“创建新凭据 → 更新环境 → 重启并验证 → 撤销旧凭据”。如果已经确认泄露，则应优先立即撤销旧凭据，再接受短时功能不可用。

Docker 部署更新后端配置：

```bash
docker compose up -d --force-recreate backend
docker compose logs --tail=100 backend
```

日志中只应确认服务启动和功能状态，不能打印 Key 本身。

历史密钥清单当前临时保存在 `~/.config/studymate/legacy-apikey.txt`。完成所有服务商轮换后，
应删除该文件，而不是长期把它当作密钥仓库。

## 泄露处理

只要 Key 曾出现在聊天、邮件正文、共享文档、截图、公开仓库、构建日志或他人电脑中，就按已泄露处理：

1. 在服务商控制台撤销旧凭据并查看异常调用与费用。
2. 创建权限更小的新凭据，更新 `backend/.env` 后重启服务。
3. 清理历史文件、CI 日志和共享副本；Git 中出现过的值即使后来删除也仍需轮换。
4. 验证相关模型、语音、Embedding 或邮件功能。
5. 记录轮换日期和负责人，但不要在记录中保存密钥值。

## 权限与备份

- `backend/.env` 和 `.deploy.env` 权限设为 `600`，所有者为部署用户。
- 不把 `.env` 放入普通项目压缩包、数据库备份或截图附件。
- 如需集中管理，使用云厂商 Secret Manager、系统密钥环或团队密码管理器，不使用 `apikey.txt`。
- 备份必须加密并限制访问；恢复到新机器后，应考虑再次轮换高权限凭据。
