# StudyMate 第四阶段最终巡检交接

日期：2026-07-29
目标：比赛评委现场可演示、真实、抓眼球、MVP 稳定

## 1. 本轮范围与安全边界

本轮只做前三阶段功能的最终巡检和增量精修，没有重写既有闭环，也没有新增 3D、开放平台、Token 管理、部署或其他大功能。

- 前端使用本机 Vite 开发服务，后端使用真实本地 FastAPI。
- 后端数据库和私有资料目录均使用临时安全副本，未修改用户原数据库或原资料目录。
- Qwen、DeepSeek、MiMo、ASR、TTS 均按“未配置”巡检；生产 OCR、外部队列、Piston 均关闭。
- 没有申请麦克风、摄像头或全屏权限，没有部署，也没有写入真实密钥。
- 私有知识库只上传了临时 TXT 演示资料；其任务最终明确进入 `ready_keyword`，没有把关键词降级伪装成向量检索。
- 报告“有数据卡”基线使用受控 fixture，只验证布局、雷达图文字和图例边界，不冒充真实用户学习成绩。
- 巡检结束后已停止本轮临时安全后端；原先已存在的前端开发服务保持运行。

### 环境启动插曲

第一次安全启动包装器使用 PowerShell 将相关环境变量赋为空字符串；PowerShell 会移除这类变量，因此后端从项目目录读取到了本地 `.env`。当时一个临时 TXT 曾显示“向量检索就绪”，因此不能排除发生过一次嵌入请求。发现后已立即停止该进程，并从不含 `.env` 的临时工作目录重启，后续巡检全部确认模型、ASR、TTS、OCR、队列与 Piston 未配置或不可用。整个交接没有记录或输出任何密钥值，也没有再触发付费生成、语音、OCR 或代码运行服务。

### 根因已正式修复

上述历史插曲和风险判断保留不变。2026-07-29 已从代码和测试工具层面完成正式修复，不再依赖“清空变量”或切换到不含 `.env` 的工作目录：

- 新增进程环境开关 `STUDYMATE_SAFE_OFFLINE=1`。配置模块在创建 `Settings` 之前读取该开关，并以 `_env_file=None` 完全跳过项目 `.env`。
- 即使父进程仍残留假设的外部凭据，后置配置约束也会把 LLM、Embedding、ASR、TTS、视觉 OCR、SMTP 和 Piston 视为未配置；生产 OCR 固定为 `unconfigured`。
- 业务入口在创建 provider/client 前显式短路；进程级 socket 保险丝继续阻止外部 DNS、TCP 和 UDP，作为遗漏与未来新增路径的第二层保护。
- B 站、人才呀和论文/图书/博客解析在该模式下不发起请求，分别返回安全离线态、内置兜底目录或空解析结果。
- 私有知识任务仍只使用本地进程内 `BackgroundTasks`，项目没有外部队列实现；TXT 只进入 `ready_keyword`，不会显示向量检索成功。
- 正式非交互启动方式为 `backend/scripts/run_safe_offline.py`。它要求显式传入隔离 SQLite 文件与私库目录，只监听环回地址，不启动 Piston。

回归测试使用仅含固定假值的临时 `.env`，并同时模拟父进程残留假 Key；断言 Qwen、DeepSeek、MiMo、星火、Embedding、ASR、TTS、OCR、SMTP 与 Piston 全部不可用，所有网络 client/mock 调用为 0。测试还实际处理临时 TXT，断言状态为 `ready_keyword`、向量进度为 0、分片向量为空。

修复后在 `STUDYMATE_SAFE_OFFLINE=1` 的进程环境中重新执行后端编译与完整 unittest，52 项全部通过。随后用正式启动器和全新临时 SQLite/私库目录完成真实本地 HTTP 冒烟：`/api/ping` 为安全离线且 LLM 未配置，Qwen/DeepSeek/MiMo 配置数 0，ASR/TTS/OCR/Piston/外部队列均不可用，代码运行返回明确离线 mock；进程已停止，临时目录已清理。该空白隔离数据库不包含课程种子，因此本次冒烟不复用原巡检中“课程 5 门”的数据断言。

验证边界：安全离线模式保证的是后端进程 0 外联，不会阻止用户在浏览器中主动点击第三方搜索链接；前端页面自身若要做全浏览器离线验收，仍需使用现有 E2E 路由 mock 或浏览器网络策略。真实服务连通性、费用、配额和质量不属于本次验证范围。

## 2. 实际发现与修复

### 2.1 私有知识库空态留白过大

原空态在 1366×768 下只有标题和页签，主体出现大面积无意义留白，评委不容易理解下一步。

已修复：

- 增加居中的数据库图标、用途说明和“命名建库 → 上传解析 → 助教引用”三步提示。
- 增加明确 CTA，点击后把焦点送到左侧知识库名称输入框。
- 任务态继续真实显示解析、向量化/关键词降级、页码和失败重试信息。

### 2.2 账号切换后残留私库选择

发现退出管理员再进入评委账号时，本地可能残留旧知识库 ID；PPT 页也会显示不友好的 `#ID`，存在跨账号观感和演示风险。

已修复：

- 用户会话重置时同步清除所选私有知识库。
- 私库页刷新后校验所选 ID 是否仍属于当前用户；无效时清空或选择当前用户的第一项。
- PPT 页在使用所选私库前先向后端校验 ID，并展示真实知识库名称；无效选择自动清理。

### 2.3 语音未配置态存在误导

原降级页仍出现“开口说话”“继续聆听”等可点击暗示，与 ASR 未配置事实冲突。

已修复：

- 主按钮明确显示“语音未配置”并保持禁用。
- 数字人气泡明确显示“演示降级 / 语音识别未配置，请使用文字模式”。
- 空对话区改为“语音服务未配置，文字学习仍可继续”，提供“继续文字学习”入口。
- 保留清晰说明：页面不会申请麦克风，文字记录仍可继续，TTS 也未配置。

### 2.4 全局数字人遮挡精确控件和数据卡

巡检发现全局数字人在 PPT 导出区、AI 视频时间轴以及 1366 宽度下的报告参与度卡片上可能造成遮挡。

已修复：

- 在 `/concept`、`/ppt`、`/report`、`/tests` 等沉浸或高密度页面收起全局数字人。
- 课程、私库等普通页面仍保留全局入口。
- 实测数字人从右下向左上拖动后没有误触打开；拖动后再次点击仍可正常打开助手抽屉并关闭。
- 语音页专用全身数字人保持完整头脚、气泡不遮脸。

当前边界保持诚实：数字人仍是五状态契约、四类姿态透明静态素材的比赛 MVP，不是连续透明视频，也没有逐音素口型。

### 2.5 PPT、视频与学习宇宙

- PPT 在三个模型均未配置时先明确提示，不会静默换模型；人工确认“使用本地策略”后生成 10 页可编辑大纲。
- 图表页、引用折叠区、来源页码和可编辑 `.pptx` 导出链路保持真实；课程与私库来源均可进入引用。
- AI 视频的字幕、时间轴、倍速、音量、暂停/重播均正常，密集控件区不再被全局数字人覆盖。
- 学习宇宙的标题、主 CTA、飞船/彗尾层级在两个视口下均未被遮挡；进入暖白学习桌面的约 1 秒转场结束后没有持续黑带或横向溢出。

## 5. 现场仍需人工确认

1. 在比赛实际笔记本、投影缩放和网络环境下走一遍 3–5 分钟演示，并录制保底视频。
2. 若现场获批使用真实模型或语音服务，应在受控设备重新检查超时、限流、费用、音量和回声；本轮没有验证任何付费服务。
3. 外部 B 站与人才呀资源受网络、登录状态和第三方页面变化影响，现场应准备不依赖外网的主链路。
4. 当前多姿态数字人素材的展示权、肖像授权和比赛传播范围仍需项目方确认。
5. 固定比赛设备上的 INP、持续动画帧率和投影色彩仍应现场实测；本轮只提供本机基线。
