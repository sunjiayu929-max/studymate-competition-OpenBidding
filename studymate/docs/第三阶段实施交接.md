# StudyMate 第三阶段实施交接

> 完成日期：2026-07-29
> 目标：在不重写第一、二阶段闭环的前提下，补齐比赛演示所需的动态数字人、独立评委路线、学习宇宙第一眼、关键路径 E2E 与静态资源预算。
> 边界：本轮没有调用真实付费模型、TTS 或 ASR，没有请求麦克风/摄像头/全屏权限，没有启动 Piston、生产 OCR、外部队列或部署，也没有初始化 Git。

## 1. 本轮已完成

### 1.1 动态数字人 2.0 MVP

- 新增 `frontend/src/lib/digitalHuman.ts`，统一定义 `idle / listening / thinking / speaking / paused` 五状态媒体契约。
- 新增 `frontend/src/components/DigitalHumanMedia.tsx`，提供同一套 `<picture>` 响应式资源、状态交叉淡化、加载优先级与 `prefers-reduced-motion` 支持。
- 全局悬浮助教 `TutorBubble` 与实时语音页 `VoiceTutor` 已复用该组件，不再各自维护一套人物逻辑。
- `thinking` 使用托腮思考姿态，`speaking` 使用自然抬手摊手讲解姿态；动作来自真实不同姿态素材，不用整个人左右摇晃冒充手势。
- `paused` 明确使用静态待机回退；轻微呼吸只改变极小幅度的纵向位置或比例。没有把这套效果描述为视频、动作捕捉或逐音素口型。
- 保留原有拖动与点击防误触，人物头脚完整；气泡仍在人物侧上方，不覆盖面部。

比赛演示人物素材位于：

- `frontend/public/digital-human/studymate-tutor-transparent.png`
- `frontend/public/digital-human/studymate-tutor-listening.png`
- `frontend/public/digital-human/studymate-tutor-thinking.png`
- `frontend/public/digital-human/studymate-tutor-speaking.png`
- 对应的 `320w / 640w` WebP 响应式版本

新增三张姿态图为 AI 生成的比赛演示素材。生成时使用项目原透明人物作为参考，以内置 ImageGen 模式分别要求：

1. 同一人物、同一发型、米白衬衫与卡其长裤，完整头脚，正面自然聆听站姿；
2. 同一人物与服装，完整头脚，一手托腮、一手自然支撑的思考姿态；
3. 同一人物与服装，完整头脚，一手自然抬起摊掌讲解、另一手放松的可见讲解手势。

生成源采用纯绿色背景，再由本地脚本 `frontend/scripts/remove_chroma_key.py` 软化边缘、去绿色溢色并导出透明 PNG。素材用途和真实性边界记录在 `frontend/public/digital-human/README.md`。

### 1.2 语音页权限与降级

- 修复实时语音页加载即尝试申请麦克风的演示风险；现在只在用户明确点击“继续聆听”后才可能调用 `getUserMedia`。
- 新增只读 `GET /api/voice/status`，只返回 ASR/TTS 配置布尔值、TTS 引擎和 `user_gesture_only` 权限策略，不签名、不调用外部服务。
- ASR 未配置时页面显示“演示降级”，不申请麦克风，保留完整文字对话并提供切回文字助教入口。
- 新增后端测试，确认无配置时状态准确且不会联系外部服务。

### 1.3 独立评委演示模式

- 新增 `frontend/src/components/JudgeDemoMode.tsx`，与普通 `JudgeTour` 完全分离。
- 入口位于左侧应用壳的克制辅助区，只向 `judge / admin` 显示。
- 使用独立 `sessionStorage` 键保存步骤；进入时记录原课程与原路径，退出、完成或复位后恢复，不覆盖画像、对话、工作台结果或其他正式用户数据。
- 启动时读取真实课程接口并选择真实“机器学习”课程；课程不存在或接口失败时明确报错，不伪造。
- 3–5 分钟路线依次覆盖：学习宇宙、课程与课程 RAG、私有知识库、学习资源工坊、可视讲解、AI 助教/语音降级、实时报告。
- 进入语音步骤时只读取模型和语音配置状态，显示“演示降级”“状态未知”或“已配置（本演示不调用）”，不会替评委触发付费调用。

### 1.4 学习宇宙与比赛版视觉回归

- 学习宇宙新增一次性进场镜头、远景行星与地平线受光、低频飞船掠过、远景彗尾、轨道光照变化、节点信号脉冲、核心星球受光/自转感和轻微鼠标视差。
- 飞船、彗尾和信号位置避开标题、主按钮与课程节点；主入口“进入今日学习”保持首屏一眼可见、可点击。

- 自动桌面回归覆盖学习宇宙 1366×768、1440×900、1920×1080，无横向溢出。
- 额外覆盖私有知识库空状态、PPT 工作流、文字助教、Qwen/DeepSeek/MiMo 未配置状态、实时报告和管理员数据健康卡在 1440×900 下的首屏标识、路由错误边界与横向溢出。

## 3. MVP 与 fallback 边界

- 数字人是四张透明姿态图的状态播放器 MVP，不是连续视频；没有口型同步。未来可在不改业务状态机的情况下，将每个状态替换为透明 WebM、MP4 或帧序列。
- `listening` 与 `idle` 的差异比 `thinking / speaking` 克制，当前依赖姿态、状态标签和波形共同表达；讲解态已有清晰抬手手势。
- `paused` 暂复用静态 idle 素材；这是明确 fallback，不伪造单独暂停动作。
- 模型、ASR、TTS 未配置时明确不可用或降级；没有自动切到其他模型，也没有模拟“服务成功”。
- 评委模式只负责路线与说明，不代替评委生成数据；报告没有学习证据时仍展示真实空状态。
- AVIF 本轮未接入：当前 WebP 已把主要资源压到预算内，继续增加编码变体的收益有限，且透明数字人需要优先保守验证边缘质量。

## 4. 未完成与下一阶段可直接接手项

以下内容不属于本轮已完成能力，不应在演示中声称已经具备：

1. 数字人透明 WebM/MP4 连续动作、动作捕捉、逐音素口型和真实视频驱动。
2. 固定评委设备、真实后端、真实网络上的 LCP/长任务采样，以及真实 INP 验收。
3. 真实 ASR/TTS/LLM 连通性、费用、配额、音色质量与弱网重连验收。
4. 生产 OCR、Piston、外部队列、开放平台、API Token、部署和复杂 3D。
5. 全量窄屏逐页截图基线；本轮优先覆盖比赛常见桌面视口，移动端只保留现有响应式实现，没有做新一轮视觉重构。
6. AI 生成数字人素材在最终参赛材料中的版权/授权文字仍需项目负责人确认；代码内已保留来源与生成方式说明。

如果继续做第四阶段，优先顺序建议为：

1. 在固定比赛电脑上人工录屏走完评委模式，并验证拖动数字人后点击防误触、气泡不遮脸、四姿态交叉淡化与减弱动态。
2. 用真实本地后端但仍关闭付费外部服务走一次课程、私库后台状态、PPT 显式 fallback、报告空/有数据状态。
3. 为登录、宇宙、工作台、私库、PPT、助教、语音降级、报告、测试管理建立 1366×768 与 1440×900 的审阅截图基线。
4. 若能取得同人物一致的连续透明素材，再替换状态媒体文件；不需要改动五状态业务契约。

- 首次进入学习宇宙观察一次性镜头；滚出首屏后确认装饰动画暂停，系统减弱动态开启时确认无进场和视差。
- 检查 1366×768 下主入口、标题、课程节点不被飞船或彗尾遮挡。
- 打开全局数字人，依次触发思考与生成状态，确认人物完整头脚、讲解态有可见摊手，拖动后不会误打开抽屉。

- 从左侧入口启动评委演示，走到语音降级与报告，退出后确认恢复进入前课程和路径。
