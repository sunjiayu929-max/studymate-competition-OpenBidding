# 每轮画像回写改动说明

> 日期：2026-08-20
>
> 范围：修复验收项 #6「每学习一轮后都更新一次画像」的缺口，并顺手修正一处陈旧测试。

## 1. 背景与问题

岗位训练闭环的画像更新此前只发生在「首轮前的理论基线测评」：`theory_assessments` 提交时会写回 `Profile.dims`、`profile.version += 1` 并保存快照。

但**每轮分阶测试的验收反馈（`POST /api/workspace/feedback`）只把结果写进 `training_runs.feedback`，没有回写 `Profile` 表**；前端的能力证据也只落在 `localStorage`。因此「每学习一轮后都更新一次画像」没有真正闭环——画像在首轮后不再随学习结果变化。

## 2. 改动内容

### 2.1 画像 schema（`backend/app/schemas/profile.py`）

- 新增 `TrainingRoundEvidence` 模型：`run_id / domain / target_role / topic / accuracy / answered_count / wrong_count / next_action / difficulty_delta / completed_at`。
- `ProfileDims` 新增 `training_rounds: list[TrainingRoundEvidence]` 字段（最新一轮在前，最多保留 20 轮）。

### 2.2 反馈接口（`backend/app/api/workspace.py`）

`submit_training_feedback` 在**有真实作答证据、且首次提交**时（重复提交不重复累加版本），额外执行：

1. 追加一条 `TrainingRoundEvidence` 到 `dims.training_rounds` 首位；
2. 按正确率更新 `dims.weak_points.topics`：达标（≥85）能力从薄弱点移除，未达标能力提到最前，供下一轮诊断优先补齐；
3. 写 `ProfileSnapshot`（保存修改前 dims）；
4. `profile.version += 1`。

`run.feedback` / `result` 的原有结构与返回保持不变，不影响前端现有读取。

### 2.3 测试（`backend/tests/test_training_loop.py`）

- 扩展 `test_feedback_endpoint_updates_owned_published_run`，补充断言画像回写（`training_rounds` 追加、`weak_points` 更新）。
- 新增 `test_feedback_mastery_bumps_version_and_clears_weak_point`，覆盖高分（≥85）时版本 +1、薄弱点移除、快照落库的分支。

### 2.4 文档（`docs/岗位训练闭环使用指南.md`）

第 8 步「反馈更新」与「可审计数据」两处已同步说明：每轮验收反馈会回写画像（训练轮次证据、薄弱点更新、版本 +1、快照）。

## 3. 附带修复：一处陈旧测试

`test_training_loop.py` 中的 `test_machine_learning_maps_to_primary_competition_role` 期望 `resolve_training_role("机器学习")` 返回「工业视觉质检算法工程师」，但当前 `backend/app/training/catalog.py` 已改为「特定软件开发 / 人工智能 / 工业互联网」三领域 15 岗位结构，「机器学习」不再有专属映射，落到通用兜底。

改为 `test_legacy_course_name_falls_back_to_generic_role`，断言当前真实兜底行为「机器学习应用工程师」，并保留「核心能力 ≥ 5」断言。

## 4. 验证结果

- `python -m compileall -q app scripts tests` 通过。
- 后端全量 `python -m unittest discover -s tests`：**88 个测试全部通过**。

## 5. 已知边界（非本次范围）

- 数据层画像已每轮回写，但前端「画像完整度 / 版本号」在反馈提交后不会自动刷新显示，需重新进入页面才能看到最新版本号；如需即时刷新，需再补一行前端重新拉取画像的逻辑。
- 本改动只解决「每轮更新画像」的数据闭环；验收项 #9「降维解释」的入口语义（做得不好时用更简单方式重学当前知识点）尚未落地，属于后续独立改动。
